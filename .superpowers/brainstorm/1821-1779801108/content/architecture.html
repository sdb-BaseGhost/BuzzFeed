前端架构方案

选择项目的技术架构方向

A

推荐：Pinia + Axios + 模块化 Composables

状态管理：Pinia（Vue 3 官方推荐，轻量，TypeScript 友好）

HTTP：Axios + 请求/响应拦截器（统一处理 JWT、错误）

逻辑复用：Composables（useFeed, useAuth, usePost 等）

Mock 策略：Axios 拦截器 + 独立 mock 模块，后期切换只需改一个配置

Pros

  • Pinia 是 Vue 3 生态标准，社区资源丰富
  • Composables 灵活复用逻辑，避免 mixin 的命名冲突
  • Mock 层与业务代码解耦，对接后端时改动最小

Cons

  • 需要手动管理 mock 数据的结构
B

轻量方案：纯 Composables + Fetch

状态管理：无全局 store，用 provide/inject + composables 管理状态

HTTP：原生 Fetch API，简单封装

Mock 策略：JSON 文件直接 import

Pros

  • 零依赖，最轻量
  • 学习成本最低

Cons

  • 全局状态管理复杂时会变得混乱
  • 缺少拦截器机制，JWT 处理需要重复代码
  • 扩展性差，功能增多后维护成本高
C

全栈方案：MSW (Mock Service Worker)

状态管理：Pinia

HTTP：Axios

Mock 策略：MSW 拦截网络请求，模拟真实 API 行为

Pros

  • Mock 在网络层拦截，业务代码完全不感知 mock
  • 对接后端时只需关闭 MSW，零代码改动
  • 支持模拟延迟、错误等边界情况

Cons

  • 额外学习成本
  • 对于简单项目可能过度设计
