微社区内容平台
项目介绍：完成从 0 到 1 的内容发布与分发系统开发，实现了内容发布、关注Feed 流推送、用户关注等核心功能，用JMeter进行实际压测，通过多次迭代逐步优化系统性能与可扩展性。
技术栈：Spring Boot+MySQL+Redis+Kafka+Caffeine+ShardingSphere
内容发布模块：
受InnoDB存储引擎启发，将内容元信息和内容主体分开存储，并采用item_info和item_record表存储满足修改需求。
基于消息队列实现「内容发布→审核中心→内容中心」的异步流转，  将十万粉丝博主的发布响应时间从 6.85s 降低到 0.903s。
使用 Redis 缓存内容元信息与短文本，可通过多实例缓存+CDN 优化高并发读性能。
针对大 V 场景引入基于 Redis 的分布式锁，结合旁路缓存模式，防止缓存失效瞬间引发的缓存击穿问题，保障热点内容高并发访问下的系统稳定性。
构建缓存作为"发布对象"，通过 Canal 监听 Binlog 日志并结合 Kafka 实现缓存自动更新与大V内容缓存预热。
关注Feed流推送模块：
对大V粉丝分发任务进行拆分并行处理，解决单线程推送瓶颈。
下拉和上滑获取内容功能，经过对业务的分析后最终采用推拉结合模式。
收发件箱构建基于 Redis ZSET + MySQL 的双层存储模型，实现 Feed 流冷热数据分层。
针对大V场景，结合 Caffeine 实现本地热点缓存，显著降低 Redis 压力。
用户关注模块：
采用 Following/Follower 冗余表结构并结合分库分表方案，优化读写性能。
使用 Redis ZSET 缓存用户关注/粉丝列表，针对大V场景仅缓存 10000 条粉丝数据。
